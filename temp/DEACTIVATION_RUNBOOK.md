# ران‌بوک غیرفعال‌سازی افزونه‌ها و Rollback (P08-T023)

> هدف: خاموش‌کردن امن Elementor و خانواده Jet* (JetEngine/JetElements/JetMenu/…)
> روی استیجینگ با صفر از دست رفتن داده، به همراه نقاط بازگشت (rollback).
> اجرای مراحل روی **استیجینگ** و پس از تایید خروجی، روی پروداکشن.

## ۰) پیش‌نیازها و نقاط Rollback (AC-02)

قبل از هر تغییری این سه نقطه بازگشت ثبت می‌شود:

| # | نقطه بازگشت | دستور/مسیر | بررسی |
|---|---|---|---|
| ۱ | بک‌آپ کامل دیتابیس | `wp db export backup-<stamp>.sql` + کپی `wp-content/database/*.sqlite` در SQLite | فایل غیرخالی + sha256 ثبت شود |
| ۲ | بک‌آپ فایل‌ها | کپی `wp-content/uploads` و `wp-content/plugins` | `du -sh` قبل/بعد یکسان |
| ۳ | وضعیت کد قالب | کامیت برچسب‌خورده قالب (`git tag pre-deactivation`) + خروجی `wp theme list` | نسخه فعال ثبت شود |

- بک‌آپ‌ها خارج از ریشه وب ذخیره شوند (مثلاً `~/backups/<stamp>/`).
- بدون ثبت هر سه نقطه، مرحله بعدی اجرا نشود (AC-03).

## ۱) ترتیب اجرا (AC-01)

ترتیب ثابت است؛ هر مرحله فقط بعد از تایید مرحله قبل:

1. **فعال‌سازی قالب عرفان‌صنعت** — `wp theme activate erfansanat` (قالب باید قبل از خاموش‌کردن هر افزونه فعال باشد؛ همه سکشن‌ها/فرم‌ها بدون Elementor رندر می‌شوند).
2. **بررسی صفحات کلیدی (همه 200)** — جدول بخش ۳؛ در صورت هر خطا، به بخش Rollback برگردید و ادامه ندهید.
3. **خاموش‌کردن Elementor** — `wp plugin deactivate elementor` (فرزند قبل از والد: المان‌های Elementor بدون JetEngine هم قابل خاموش‌کردن‌اند).
4. **خاموش‌کردن Jet\* به ترتیب وابستگی** — اول `jet-engine`، سپس `jet-elements`، `jet-menu`، `jet-tabs`، `jet-popup`، `jet-smart-filters` (افزونه‌هایی که widget/فیلتر ثبت می‌کنند قبل از افزونه‌های تزئینی).
5. **بررسی مجدد صفحات کلیدی (همه 200)** — همان جدول بخش ۳؛ لاگ PHP حتماً خالی از fatal باشد.
6. **ممیزی نهایی** — اجرای `temp/tools/staging-migration-dry-run.sh` (شمارش پست/ترم/متا قبل و بعد باید drift=0 باشد) و `wp option get active_plugins` (فهرست نهایی ثبت شود).

قاعده کلی: **هیچ‌گاه uninstall/Delete Data نکنید** — فقط Deactivate.

## ۲) قواعد عدم از دست رفتن داده (AC-03)

- دیتای JetEngine در همان `wp_postmeta` استاندارد است؛ قالب عرفان‌صنعت آن را با
  `LegacyMeta` می‌خواند (فرمت PHP-serialized / JSON `item-0` بدون تغییر حفظ
  می‌شود). خاموش‌کردن افزونه چیزی از متا حذف نمی‌کند — **فقط Deactivate، بدون
  «Delete data / uninstall»**.
- منوها در `wp_terms`/`wp_options` استانداردند؛ قالب لوکیشن‌های منوی خودش را
  مستقل از JetMenu ثبت می‌کند.
- `wp-content/uploads` (رزومه‌ها در `es-resumes/`، کاتالوگ‌ها) دست‌نخورده می‌ماند.
- در صورت نیاز به بازگشت، هیچ پاکسازی دیتابیسی لازم نیست — فقط فعال‌سازی مجدد.

## ۳) چک‌لیست صفحات کلیدی — هر مورد باید HTTP 200 (SC-02)

| صفحه | مسیر |
|---|---|
| خانه | `/` |
| فروشگاه | `/shop/` |
| تک‌محصول | یک URL محصول منتشرشده |
| پروژه‌های برگزیده | `/project/` |
| تک‌پروژه | یک URL پروژه منتشرشده |
| وبلاگ | `/blog/` |
| تک‌مقاله | یک URL نوشته منتشرشده |
| خدمات | `/smartelement/` |
| تماس با ما | `/تماس-با-ما/` |
| استخدام | `/recruitment/` |
| جستجوی ایجکس | `admin-ajax.php?action=es_product_search` با nonce معتبر |

بررسی سریع: `for u in ...; do curl -s -o /dev/null -w "%{http_code} $u\n" "$u"; done`
(همه باید 200 باشند؛ 30x به 200 دنبال شود.)

## ۴) سناریوی Rollback (SC-01) — روی استیجینگ تمرین شود

تمرین استاندارد روی کپی استیجینگ (الگوی `staging-migration-dry-run.sh`):
کپی دیتابیس → شبیه‌سازی خاموش‌کردن (`active_plugins` بدون Jet*/Elementor) →
رندر صفحات کلیدی → بازگردانی بک‌آپ → تطبیق شمارش پست/ترم/متا (drift=0).

بازگشت واقعی، به ترتیب معکوس:

1. `wp plugin activate jet-engine jet-elements jet-menu jet-tabs jet-popup jet-smart-filters elementor` (همان ترتیب ثبت‌شده در گزارش).
2. در صورت تغییر کد قالب: `git checkout pre-deactivation` / بازگردانی نسخه قالب.
3. بازگردانی دیتابیس از بک‌آپ فقط در صورت خرابی دیتا: `wp db import backup-<stamp>.sql` (کپی SQLite: جایگزینی فایل پس از توقف وب‌سرور).
4. چک‌لیست بخش ۳ دوباره؛ همه 200.
5. ثبت نتیجه در گزارش مهاجرت (`temp/migration-reports/`).
